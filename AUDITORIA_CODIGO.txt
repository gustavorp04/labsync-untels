  PROBLEMA 1 — HAY CÓDIGO QUE NADIE USA (código muerto)

Son archivos o funciones que están escritos pero nunca se ejecutan.
El riesgo: quien lea el código pierde tiempo entendiendo algo que no hace nada.

ARCHIVO: frontend/src/services/labService.js
------------------------------------------------------------
Tienes DOS archivos de servicios para laboratorios:

  - laboratorioService.js  → el actual, usa autenticación, endpoints /v1/ correctos

DOBLE QUERY DE CARRERA/CICLO EN EL LOGIN
------------------------------------------------------------

================================================================================
  PROBLEMA 3 — BUG SILENCIOSO EN LA CANCELACIÓN DE RESERVAS
================================================================================

------------------------------------------------------------
ARCHIVO: backend/reservas/views/reserva_views.py  (líneas 175–177)
------------------------------------------------------------
Cuando un usuario cancela una reserva, el aforo del horario se calcula así:

  horario.capacidad_ocupada = max(0, cap_actual - cant_reserva)  ← manual

El problema: si dos usuarios cancelan al mismo tiempo, ambos leen el mismo
valor de cap_actual antes de que el otro guarde, y el resultado queda mal.

En el resto del código existe recalcular_capacidad(horario) que recalcula
sumando desde la base de datos (más seguro). El propio código tiene un
comentario que dice "recalcular_capacidad es la fuente de verdad".

ACCIÓN: Reemplazar esas 3 líneas por:
  from ..services.reserva_service import recalcular_capacidad
  recalcular_capacidad(horario)


================================================================================
  PROBLEMA 4 — ESTRUCTURA (menos urgente)
================================================================================

------------------------------------------------------------
ViewSets genéricos que bypasean la lógica de negocio
------------------------------------------------------------
En api_views.py hay ViewSets CRUD genéricos que dan acceso directo a la BD.
En reserva_views.py hay views específicas con todas las validaciones.

El problema: reservaService.js tiene una función eliminarReserva() que llama
al DELETE del ViewSet genérico. Eso borra la reserva directo sin pasar por:
  - el historial de cambios
  - recalcular capacidad
  - nada de lógica de negocio

No es lo mismo "cancelar" (con lógica) que "borrar" (sin lógica).

------------------------------------------------------------
Clase de permiso definida dentro de una función
------------------------------------------------------------
En api_views.py, dentro de get_permissions(), hay una clase IsOwnerOrAdmin
que se crea como clase nueva en cada request HTTP. Es legal pero raro,
difícil de testear y difícil de encontrar.

ACCIÓN: Moverla a utils/auth.py junto con las demás clases de permisos.
